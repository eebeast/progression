Where things live.

Vercel serves files. Your browser saves local records. Supabase Auth identifies the account. PostgreSQL receives accepted sync changes.

Open the interactive lessonDomain glossary

One complete save

React screen → WorkoutRepository → IndexedDB record + outbox transaction → observable UI update → sync_push → PostgreSQL acknowledgement → sync_pull on another device → that device's IndexedDB → its screen.

The record/outbox transaction applies in account mode. Local-only saves have no account outbox upload. A failed request leaves the operation pending; a version conflict needs review. Foreground sync is automatic while the app is open/resumed and connected.

Each private table's user_id references auth.users. Exercise/session references inside payloads are validated by the push function, not ordinary SQL FK columns. Both sync RPCs require authentication. SQL Editor inspection uses elevated project access.

Inspect without changing anything

See live records grouped by logical kind:

select store, count(*) as live_records
from workout_private.records
where data is not null
group by store
order by store;

Inspect the JSON saved for exercises:

select id, jsonb_pretty(data) as saved_payload
from workout_private.records
where store = 'exercises' and data is not null
limit 10;

Inspect individual saved sets:

select id,
       data->>'exerciseName' as exercise,
       data->>'sessionId' as session,
       data->>'weight' as weight,
       data->>'reps' as reps_or_seconds
from workout_private.records
where store = 'logs' and data is not null
limit 20;

These SQL Editor queries can include multiple accounts. Use a specific account filter when comparing a phone's data. A null payload marks deletion; a missing property inside a live payload also extracts as SQL NULL. Those are different cases.

Stored, derived, proposed

Stored

Exercise names, performed set values, session dates, run measurements, body weight, saved height and optional explicit category.

Derived in the app

Missing category fallback from known names, PRs, streaks, charts and BMI. Displayed values need not have their own database field.

Proposed only

Shared catalog releases, database-managed categories/presets/aliases, stable category IDs and their migration. No shared catalog tables exist yet.
